## P4 Adversarial Review

**OneSurplusGammaHankel.lean**

1. **`factorialProduct_shift_one` induction gap**: The inductive step rewrites via `Fin.prod_univ_castSucc` and appeals to `ih`, but the algebraic bridge from `(n.factorial * ∏...)` to the shifted product is handled entirely by `ring` after casting. The lemma asserts an equality over `ℂ` where both sides involve squared factorials reorganized into consecutive pairs. This is arithmetically correct, but the proof relies on `simp` producing exactly the right factored form for `ring` to close—no explicit justification that the cast of `Nat.factorial_succ` distributes correctly through the product before `ring` is invoked. Low risk, but worth noting as a potential fragility point if upstream casting lemmas change.

2. **`upperGammaHankel_one_surplus_det` functional definition**: The linear functional `F` is defined as `factorialMomentFunctional.comp (LinearMap.mulLeft ℂ (X + C (x : ℂ)))`. The subsequent evaluation `F ((X + C (x : ℂ))^(i.val + j.val))` implicitly requires that composing with left-multiplication by `(X + C x)` and then evaluating at powers of `(X + C x)` reduces to evaluating the original functional at `(X + C x)^(i+j+1)`. The `dsimp` + `rw [pow_succ']` step handles this, but the proof assumes `LinearMap.mulLeft_apply` and `LinearMap.comp_apply` unfold to give exactly `factorialMomentFunctional ((X + C x) * (X + C x)^(i+j))`, which then requires `mul_pow` or `pow_succ'` to commute. This is semantically fine but the intermediate `change` goal hides a non-trivial associativity of polynomial multiplication under the functional.

3. **Type coercion consistency**: The theorem statement produces a `ℂ`-valued determinant equal to an expression involving `Real.exp (-(n : ℝ) * x) : ℂ`. The hypothesis `hx : 0 ≤ x` is over `ℝ`, but `x` is used both as a real argument to `upperGammaNat` and coerced to `ℂ` inside `F`. No gap, but the proof depends on `upperGammaNat_eq_factorialMoment` accepting the real `hx` while the rest of the computation lives in `ℂ`. If that imported lemma's signature requires additional measurability or domain conditions beyond `0 ≤ x`, they are not visible here.

**Theorem1CentralOneSurplus.lean**

4. **`theorem1CentralOneSurplus_PsiDet` index arithmetic**: The `congr 1` step requires `(n+1) + n - (i.val+1) - (j.val+1) = (n - (i.val+1)) + (n - (j.val+1)) + 1`, closed by `omega`. This is correct only because `i : Fin n` guarantees `i.val < n`, so `n - (i.val + 1)` does not underflow. However, the theorem quantifies over all `n : ℕ` including `n = 0`, where `Fin 0` is empty and the matrix is `0 × 0`. The `ext i j` step vacuously holds for `n = 0`, but the downstream call to `upperGammaHankel_one_surplus_det` must also be valid at `n = 0`. Check whether that lemma's imported dependencies (e.g., `shifted_polynomial_moment_det`) handle the empty-matrix case without requiring `0 < n`.

5. **`theorem1CentralOneSurplus_candidate_eq_polynomial` division safety**: The `field_simp` step relies on `hD` (product nonzero) and `Complex.norm_of_nonneg (oneExtraRowMinimumPolynomial_nonneg n x hx)`. The nonnegativity lemma for the minimum polynomial is imported; if it requires `0 < n` or additional constraints on `x` beyond `0 ≤ x`, those are not stated here. At `n = 0`, the product over `Fin 0` is `1` and the polynomial evaluates to `1`, so the formula works, but again this boundary case should be explicitly verified against the imported lemma's actual statement.

The RHS invokes a probability measure on `ComplexSample` with parameters `(m := n+1) (n := n)`. If that imported theorem's signature requires additional regularity (e.g., Borel measurability of the sublevel set `{z | ... ≤ x}`, or that the Gaussian measure is complete), those obligations are inherited silently. No mathematical error in the claim itself, but the entire probabilistic content is delegated to an unchecked import.
