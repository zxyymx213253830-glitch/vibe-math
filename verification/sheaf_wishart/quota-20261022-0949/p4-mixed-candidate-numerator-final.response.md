## P4 Adversarial Review: MixedCandidateNumerator.lean

**1. Critical Mathematical Gap: `vandermonde` API Mismatch**
The proof of `hv` in `mixedSeriesNumerator_permute` asserts `Matrix.vandermonde (fun i => x (σ i)) = (Matrix.vandermonde x).submatrix σ id` by `rfl`. This is mathematically suspect. The Vandermonde matrix has entries $x_i^j$. Permuting the input vector $x$ by $\sigma$ permutes the **rows** of the matrix. However, `.submatrix σ id` permutes rows by $\sigma$ and columns by `id`. While this correctly describes a row permutation, standard Mathlib's `Matrix.vandermonde` is not definitionally equal to this submatrix operation under arbitrary permutations without proof that the monomial structure is preserved. If `Matrix.vandermonde` is defined via `fun i j => x i ^ j.val`, then `rfl` might hold definitionally, but this relies on the specific internal implementation of `vandermonde` rather than a mathematical property. **This is an actual gap**: relying on `rfl` for definitional equality of matrix constructors under permutation is fragile and likely masks a missing lemma about how `vandermonde` interacts with `Equiv.Perm`. If the imported `vandermonde` differs even slightly (e.g., uses a different indexing or coercion), this `rfl` silently fails or proves the wrong statement.

**2. Critical Mathematical Gap: `infiniteMixedKernel` Permutation Behavior**
The claim `hk` asserts that permuting the input $x$ in `infiniteMixedKernel` equals `.submatrix σ id` of the original kernel matrix. This is stated as `rfl`. Unlike Vandermonde, the kernel matrix entries depend on both row and column indices in potentially complex ways (Bessel functions, mixed-rank terms). Asserting that permuting the spatial variables $x$ corresponds to a simple row-permutation (`.submatrix σ id`) of the output matrix is a **strong structural claim** about the kernel's symmetry. It is not generically true for arbitrary kernels. This must be justified by the specific definition of `infiniteMixedKernel`. If the kernel matrix is $K_{ij} = f(x_i, \lambda_j)$, then permuting $x$ permutes rows. But if it involves interactions like $f(x_i, x_j)$ or mixed terms, `.submatrix σ id` is incorrect. Treating this as `rfl` is a likely mathematical error unless the source definition is trivially row-decoupled.

This is mathematically correct for producing a strictly monotone rearrangement. However, the permutation `σ` is constructed via `e.trans o.toEquiv.symm`. This chain of equivalences is type-theoretically valid but obscures whether `σ` acts on indices or values. No mathematical gap here, but high verification risk.

**5. Positivity Proof Relies on Unstated Assumptions about Imports**
`mixedSeriesNumerator_pos` invokes `generalizedMonomialVandermonde_det_pos` with exponent vector `fun i => i.val`. This assumes the Vandermonde is exactly the monomial matrix with exponents $0, 1, \dots, n-1$. If the imported `Matrix.vandermonde` uses different exponents or conventions, this application is semantically mismatched. Furthermore, `infiniteMixedKernel_det_pos` is treated as a black box; its signature must accept exactly the hypotheses provided (`hg`, `hp`, `hl`, `hlp`). The explicit assumptions `hlp : ∀ i, 0 < lambda i` and `hxp : ∀ i, 0 < x i` are sufficient *only if* the imported positivity theorem requires strict positivity of all parameters. No gap in explicit assumptions, but potential signature mismatch with dependencies.
