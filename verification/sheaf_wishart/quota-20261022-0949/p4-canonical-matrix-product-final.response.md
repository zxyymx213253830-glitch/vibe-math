## P4 Adversarial Review: `CanonicalMatrixProductInverse.lean`

**1. Critical index type mismatch (mathematical gap, not API).**
The eigenvalue index `i : Fin (Fintype.card (Fin n))` reduces to `i : Fin n`. The hypothesis `hi : i.val + 1 = min m n` therefore forces `min m n ≤ n`. However, `m = a + c` and `n = b + c` (via the equivalences `er`, `ec`), so `min m n = min a b + c`. The condition becomes `min a b + c ≤ b + c`, i.e., `min a b ≤ b`, which is fine. But the *same* theorem also requires `j : Fin b` with `hj : j.val + 1 = min a b`, forcing `min a b ≤ b` (ok) and `k : Fin c` with `hk : k.val + 1 = c`, forcing `c ≤ c` (ok). The real problem: the downstream imported result `canonical_product_inverse_realMoment_integrable_iff` is invoked with all three indices `i, j, k` simultaneously pinned to their respective **maximum** eigenvalue positions (`+1 = min ...`). If the imported theorem actually requires these specific extremal indices, this is consistent. But if it quantifies over arbitrary indices or requires a different alignment between the block-critical index and the product-critical index, the specialization here is unsound. **Verify that the imported theorem's signature semantically matches supplying all three extremal indices at once.** A mismatch would invalidate both main theorems.

**2. Measurability of `.inv.pow_const p` for non-strictly-positive base (potential gap).**
In `hF`, the code writes `(measurableCoordinate ...).inv.pow_const p`. The coordinate is an eigenvalue of a positive-*semi*definite matrix. It can be zero. The function `x ↦ x⁻¹^p` on `[0,∞)` involves `0⁻¹ = ∞` (or undefined behavior depending on the formalized convention). The proof of integrability/divergence treats this as a real-valued measurable function, but when the eigenvalue is exactly zero, `ENNReal.ofReal ((0 : ℝ)⁻¹ ^ p)` in the lintegral theorem needs care. The `ae_of_all` claim uses `inv_nonneg.mpr (complexGram_eigenvalues₀_nonneg ...)`, yielding `x⁻¹ ≥ 0` pointwise. If `x = 0`, then `x⁻¹ = 0` in Lean's totalized inverse, so `0 ^ p = 0` since `p > 0`. This means the integrand is **zero** on the locus where the eigenvalue vanishes, not infinite. **This contradicts the mathematical intent**: the inverse moment should diverge near zero eigenvalues, not vanish. The totalized `⁻¹` on `ℝ` silently destroys the singularity. This is a genuine semantic error in the lintegral theorem's setup—the `ENNReal.ofReal` of a totalized-zero inverse gives `0`, not `⊤`, making the divergence claim unprovable as stated unless the Gaussian law gives measure zero to the singular locus (which it does, but this isn't leveraged; the `ae_of_all` bound is pointwise everywhere).

**3. Missing positivity constraint on `max a b - min a b + 1` (minor).**
The threshold `(max a b - min a b + 1 : ℕ) : ℝ` is always `≥ 1` since `a, b > 0`, so `hp0` derivation is valid. No issue here.

**Summary:** Problem 2 is a hard mathematical gap—totalized real inverse eliminates the singularity the divergence theorem claims to detect. Problem 1 requires confirming the imported theorem accepts three simultaneous extremal indices.
