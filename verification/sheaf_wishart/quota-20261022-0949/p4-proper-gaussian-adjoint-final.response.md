## P4 Adversarial Review: `ProperGaussianAdjointLaw.lean`

**1. Missing definition of `Complex.conjLIE` (semantic gap risk).**
The proof of `standardComplexScalarLaw_map_conj` depends on `stdGaussian_map Complex.conjLIE`. The identifier `conjLIE` is not defined in this file. If it denotes the real-linear isometric equivalence implementing complex conjugation, then `stdGaussian_map` (which requires a suitable orthogonal/unitary invariance statement) applies correctly. However, if `conjLIE` is merely a measurable function without the isometric or linear structure that `stdGaussian_map` demands, the invocation is unsound. The `rfl` proof that `conjLIE = star` does not by itself guarantee that `conjLIE` carries the typeclass instances (e.g., `Isometry`, `LinearMap`) required by `stdGaussian_map`'s signature. This is an **actual dependency mismatch concern**, not a mere API question: the semantic content of `conjLIE` must include both pointwise equality to `star` and whatever structural properties `stdGaussian_map` assumes.

**2. Commutation rewrite uses implicit measurability of scalar multiplication.**
In `standardComplexScalarLaw_map_conj`, the step `rw [he, ← Measure.map_map ...]` relies on `fun_prop` to discharge measurability of `(Real.sqrt 2)⁻¹ • z` and `star`. While standard, this silently requires that scalar multiplication by `(Real.sqrt 2)⁻¹` is Borel-measurable as a map `ℂ → ℂ`. This is true but non-trivial when working over the complex field with the real scalar action; it depends on the identification of `ℂ` with `ℝ²`. Not a gap, but a fragility point if upstream topology changes.

**3. `matrixLawEntries` uses `erw` rather than `rw` for `map_map`.**
The `erw` in `complexGaussianMatrixLaw_conjugate` at `erw [Measure.map_map ...]` suggests definitional equality does not close cleanly. This is typically benign, but combined with the subsequent `have he` block—which proves a pointwise equality of composed functions via `funext` and `star_add`—the proof relies on the fact that `Measure.map` respects pointwise-equal functions extensionally. This holds in Mathlib (`map_congr`), but the `erw`/`simp_rw` chain does not explicitly invoke `map_congr`; it trusts that the definitional unfolding plus `he` suffices. If `Measure.map_map` produces a term requiring congruence closure rather than syntactic equality, this could mask a **silent gap**. Recommend verifying that `erw` here is genuinely necessary and not hiding a missing `congr_arg`.

**4. `shiftedTranspose` invokes `stdGaussian_map` without explicit invariance witness.**
The final rewrite in `shiftedTranspose` applies `stdGaussian_map` after reindexing via `complexSampleTransposeReindex`. This requires that the transpose-reindex map preserves the standard Gaussian measure. The proof supplies measurability and continuity but does not explicitly state that `complexSampleTransposeReindex` is an orthogonal transformation (or isometry) of the underlying real Hilbert space. If `stdGaussian_map` requires only measurability, this is fine; if it requires isometric/orthogonal structure (as is typical for Gaussian invariance under coordinate permutation), the omission is a **mathematical gap**—the invariance claim is being used but not established in this proof body.

**5. Empty-dimension edge case (`m = 0` or `n = 0`).**
The docstring claims coverage of "empty dimensions." When `m = 0` or `n = 0`, `Fin m × Fin n` is empty, and `standardComplexPiLaw` reduces to a Dirac mass on the unique empty function. The `funext` proofs in `he` blocks quantify over `z : (Fin m × Fin n) → ℂ` and `i : Fin m`, `j : Fin n`; these are vacuously true in empty cases. No actual gap, but the `by fun_prop` measurability side-conditions on maps between empty-type matrices should be confirmed to resolve without requiring `[Nonempty (Fin m)]` instances.
