## P4 Adversarial Review: `PaperPsiTailMomentBridge.lean`

**1. Missing integrability hypotheses (mathematical gap).** Theorems `mixedCandidateTailMatrix_central` and `_noncentral` rewrite the entries of `mixedCandidateTailMatrix` using `setIntegral_congr_fun`. This requires the integrands to be a.e.-measurable and the integrals to be well-defined (or interpreted as extended reals). No integrability or measurability side-conditions are assumed. The `simp`/`ring` closure hides the fact that pointwise equality of integrands does not automatically yield equality of Lebesgue integrals over `Ioi x` without a dominating function or explicit `IntegrableOn` proofs, especially when `q` or `mixedMomentDegree` are large enough to create non-integrable singularities at infinity.

**2. Unjustified use of `if_pos hy0` (mathematical gap).** Both central and noncentral proofs invoke `if_pos hy0` where `hy0 : 0 < y` derived from `hx : 0 ≤ x` and `hy : y ∈ Ioi x`. This assumes `mixedEnsembleF` and `mixedEnsembleG` are defined via an `ite` that selects on `0 < y`. However, no such definition is visible in this file. If the actual definitions branch on a different condition (e.g., `0 ≤ y` or a parameter-dependent threshold), this rewrite is semantically invalid. The reviewer must verify the exact `ite` structure of the imported ensemble functions matches `hy0`.

**3. `scalarSeriesKernel` parameter ordering (convention mismatch risk).** In `_noncentral`, the term `scalarSeriesKernel q (lambda j) y` appears. The Nuttall series tail bridge import likely defines `scalarSeriesKernel` with a specific parameter order (order, parameter, argument). If the imported definition uses `(parameter, order, argument)` or similar, this application silently swaps semantics. This is not a Lean type error if all arguments are `ℝ`/`ℕ`-coercible, but it produces a mathematically wrong kernel. Exact signature match required.

**4. `psiTailColumnFactor` square root domain (mathematical gap).** The factor `(Real.sqrt (lambda j))^q` in `psiTailColumnFactor` is only real-valued and meaningful when `lambda j ≥ 0`. The theorem `paperPsi_tail_matrix_transport` assumes `hl : ∀ j, 0 ≤ lambda j`, so this is covered *at the call site*. However, `psiTailColumnFactor` itself is defined without this guard. Any downstream use outside `transport` without nonnegativity produces complex/nan pollution silently. Either the definition should carry the hypothesis or document the partiality.

**5. Equiv index arithmetic fragility (potential gap).** The proof of `hr` uses `Fin.val_rev` and `omega` to establish `p+L-((Fin.rev (finSumFinEquiv i)).val+1) = mixedMomentDegree p L i`. This arithmetic identity depends on the *exact* internal definition of `mixedMomentDegree`. If that definition changes by even a constant offset in a dependency, this proof breaks silently because `omega` closes goals based on current unfolded forms. Not a bug now, but a maintenance-critical fragility that should be pinned by an explicit `@[simp]` lemma in the defining module.

**6. `Complex.ofRealHom.mapMatrix` coercion (API question).** The final transport theorem maps a real matrix through `ofRealHom`. This is algebraically fine, but relies on the ring homomorphism instance being definitionally the one expected by `theorem1PsiEntry`'s codomain. If the paper's Psi matrix lives in a different complex structure (e.g., `ℂ` vs `CliffordAlgebra`), this equality is type-correct but semantically vacuous.
