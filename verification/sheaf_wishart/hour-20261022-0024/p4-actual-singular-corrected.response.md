## P4 Adversarial Review

**1. Critical: `abs_positive_log_sum_le_minor_log` fails for q=0.**
When `q=0`, the minor determinant is the empty matrix with `det=1`, so `hp : 1≠0` holds trivially. However, the bound contains `2*|Real.log ‖(X.submatrix f g).det‖| = 0` and `|Real.log (0.factorial)| = 0`. The LHS `|∑ i, positiveSpectrumLog λᵢ|` can be strictly positive when eigenvalues lie in (0,1), since `positiveSpectrumLog x = log x < 0` there. With `hr : X.rank = 0` forcing all eigenvalues to be exactly 0, the sum is empty and equals 0, so the inequality `0 ≤ 0` holds—but only vacuously through the rank constraint, not the domination logic itself. The proof's use of `hl` requires `q ≥ 1` for the factorial coefficient bound to carry information; at `q=0` the cited `squared_coordinate_minor_le_factorial_coefficient` yields `1 ≤ 1·c₀`, which after logarithm gives `0 ≤ log c₀`, providing no upper control on a potentially negative log-sum if the rank premise were relaxed.

**2. Critical: Domination sign error from negative log values.**
The clarification states `positiveSpectrumLog x = log x` for `x ∈ (0,1)`, which is negative. The theorem name `positiveSpectrumLog_le_self` and its documented proof via `log x ≤ x - 1` give `positiveSpectrumLog x ≤ x - 1 < x` for `x > 0`. In `abs_positive_log_sum_le_minor_log`, the bound `hu` uses `positiveSpectrumLog_le_self` to conclude `∑ positiveSpectrumLog λᵢ ≤ ∑ λᵢ`. This is correct for the **upper** bound. But the **absolute value** on the LHS means we need `|∑ positiveSpectrumLog λᵢ| ≤ ...`. When many eigenvalues fall in (0,1), the sum is large-negative, so `|sum| = -sum`. The lower bound in `apply abs_le.mpr; constructor` is dispatched by `linarith [neg_le_abs ..., le_abs_self ...]`, but these facts about `Real.log ‖det‖` and `Real.log q!` do not establish `-∑ positiveSpectrumLog λᵢ ≤ RHS` unless one separately proves `∑ λᵢ + |log q!| + 2|log|det|| ≥ -∑ log λᵢ` for small eigenvalues. The current `linarith` call cannot close this because `hu` only flows in the wrong direction for the negative case.

**3. Major: `exists_actual_fixed_rank_minor_log_witness` assumes r>0 implicitly.**
When `r = min m (fromRows B M).rank = 0`, the index type `Fin 0` is empty. The `obtain ⟨f,g,hf,hg,hdet⟩` from `exists_rank_coordinate_minor` at rank 0 produces functions from an empty type, making `L` and `H` both 0×0 or degenerate. The subsequent call to `integrable_actualAffineCompressedDet_log B M L H` requires `L` to be `r×m` and `H` to be `n×r`; at `r=0` these are 0-row/0-column matrices. No explicit handling ensures the compressed determinant remains the nonzero constant 1 (empty det), so `hlog` integrability and `hp : genericAffineCompressedDet ≠ 0` may fail or become ill-typed depending on whether the API defines 0×0 determinants as 1.

**4. Minor: `complexSampleMean` evaluation at zero matrix.**
In `hm : complexSampleMean (0 : Matrix ...) = 0`, this unfolds definitionally, but the subsequent `simpa only [hm, add_zero]` rewriting `sampleEval z p + complexSampleMean 0` to `sampleEval z p` assumes the affine model is `Z ↦ Z·B + M + mean(0)·B`. If `complexSampleMean` extracts a deterministic offset already baked into `M`, double-counting or omission could occur. Not a gap if the definition is `z·B + M` with zero-mean noise, but worth flagging.
